💡 Propuesta de valor: "Hoy tenés 2-3 personas tomando turnos por teléfono, WhatsApp y mostrador. SetubalAI reemplaza esa operación con un agente IA que funciona solo, 24 horas, y le da a la clínica datos reales para gestionar."

Dos personas, dos usos:

👤 Cuando el PACIENTE interactúa:

Usa el Bot de Telegram. Escribe por chat, el agente le ofrece especialidades, horarios y confirma el turno. No toca la web app nunca.

👥 Cuando el PERSONAL de la clínica interactúa:

Usa la Web App. Ve turnos agendados, atiende pacientes, registra atenciones, consulta historiales, gestiona horarios y configuración.

3. Bot Agente IA (Telegram)

FUNCIONAL — @SetubalClibot

El paciente interactúa como si hablara con una recepcionista real. Sin formularios, sin apps, sin web. Solo escribe por Telegram.

Menú Principal (5 opciones con botones inline)

BotónFunciónFlujo
📅 Agenda TurnoFlujo completo de agendadoEspecialidad → Médico → Slot Horario → Confirmación
🔄 ReprogramarCambiar fecha/hora de turnoBuscar turno → Nuevo slot → Confirmar cambio
❌ Cancelar TurnoAnular turno existenteMostrar turnos → Seleccionar → Confirmar cancelación
📋 Mis TurnosVer turnos pendientesLista de turnos futuros del paciente
❓ AyudaInformación de usoMuestra opciones disponibles

🔧 Funcionalidades Avanzadas del Bot

  • Identificación automática por Telegram ID — Si ya es paciente vinculado, salta directo al menú sin pedir DNI
  • Creación inline de pacientes nuevos — Si no existe, registra durante el flujo: nombre, DNI, obra social, teléfono
  • Auto-vinculación — Al identificarse por DNI, guarda automáticamente el chat_id para futuras interacciones
  • Detección de intención por texto — Entiende si quiere agendar, cancelar o ver turnos sin usar el menú
  • Anti-duplicados por especialidad — NO permite 2 turnos pendientes para la misma especialidad
  • Menú contextual — Después de cada acción, ofrece botones para continuar o volver
  • Comando /vincular DNI — Vincula manualmente un chat existente a un paciente
  • State machine robusta — 3 capas anti-abuse, tracking de conversaciones por chat_id

📝 Flujo Completo de Agendado

1

Paciente escribe "Hola, quiero turno"

Bot detecta intención → Busca paciente por chat_id → Si no existe, pide DNI

2

Identificación

Si DNI existe → carga datos → Si no existe → pide nombre, apellido, obra social, teléfono → Crea paciente en DB

3

Eligir Especialidad

Bot consulta DB → Muestra especialidades disponibles con botones inline → Paciente selecciona

4

Eligir Médico

Bot consulta médicos de esa especialidad → Muestra opciones → Paciente selecciona

5

Buscar horarios disponibles

Bot genera slots basados en grillas médicas del médico seleccionado → Filtra turnos ya ocupados → Muestra horarios con botones

6

Confirmación

Paciente elige slot → Bot verifica última disponibilidad → Crea turno en DB (visitas) → Envía confirmación con todos los datos

11. Multi-Tenant (SaaS Real)
